## 4. Deployment & rollback note

- **Apply:** `npx prisma migrate deploy --schema prisma/schema.prisma` (CI already runs this step before tests; Cloud Run migration job in #74).
- **Why not automatic down-migration:** PostgreSQL cannot remove an enum value with a plain `ALTER TYPE ... DROP VALUE`. Rollback therefore requires a *new* forward migration with an explicit type rebuild.
- **Documented rollback procedure:** (1) create a new enum type with the original three values; (2) rewrite `status`/`action` columns via a temporary cast using the literal values, rejecting any row that uses a Sprint 2 value; (3) drop old types and rename; (4) drop `Attachment`, then drop the two `stage` columns. Because no Sprint 2 data exists before the feature PRs merge, step (2) affects zero rows in practice.
- **Safety rule:** never edit an already-applied migration file; any correction is a new migration reviewed under this issue.
