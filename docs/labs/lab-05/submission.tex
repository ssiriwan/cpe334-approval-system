\section*{Answer Part 1: CI and Quality Gate (30 points)}
\label{part:1}
% =====================================================================

\textbf{Workflow:}
\href{https://github.com/ssiriwan/cpe334-approval-system/blob/main/.github/workflows/ci-docker.yml}{.github/workflows/ci-docker.yml}
--- one job named \textbf{CI quality gate} (job id \texttt{test-and-docker}). On every PR into
\texttt{lab5-staging}, \texttt{sprint-1-staging} and \texttt{main} it starts PostgreSQL 17 as a
service, applies migrations, seeds the demo accounts, runs the full 34-test Vitest suite
(API/DB integration tests for BR-01--BR-07 plus component tests), builds client and server,
builds the Docker image, starts the container and asserts that \code{/api/health} reports the
commit under test.

\subsection*{1.1 C-01 --- a normal PR runs the build and all tests (R-05)}
\href{https://github.com/ssiriwan/cpe334-approval-system/pull/26}{PR \#26} was reviewed by a
teammate and merged. \href{https://github.com/ssiriwan/cpe334-approval-system/actions/runs/44777880489}{Actions run 44777880489}:
\textbf{CI quality gate: SUCCESS} (2m10s) at commit \texttt{38d7211} --- 7 test files,
\textbf{34 passed / 0 failed / 0 skipped}; the container health smoke test also passed.
A second green run after adding \texttt{lab5-staging} to the triggers is
\href{https://github.com/ssiriwan/cpe334-approval-system/actions/runs/44873769377}{44873769377}
(PR \#28). The suite is not smoke-only: \texttt{TEST-05..13} exercise self-approval blocked
before assignment, state transitions, unrelated-reviewer denial and decision validation
against a real database.

\subsection*{1.2 C-02 --- a failing PR cannot be merged (R-06)}
Rulesets \textbf{lab5-protect-main} (27451785) and \textbf{lab5-protect-staging} (27451799) are
active: pull request + one approval + required status check \textbf{CI quality gate}, force push
and deletion blocked, no bypass actors. \href{https://github.com/ssiriwan/cpe334-approval-system/pull/24}{PR \#24}
from the temporary branch \path{lab5/c02-failing-check} added one deliberately failing test
(commit \texttt{28c45e3}). The check reported FAILURE and GitHub reported
\code{mergeStateStatus = BLOCKED}. The PR was closed on 17 Nov without merging; the released
application was never touched.

\subsection*{4.2 Known limitations and AI-use declaration}
\begin{itemize}[leftmargin=*]
\item No separate cloud staging environment, canary or load tests (not required by Lab 5 Section 4.2). Rollback is documented manually in \path{deployment.md}; no automated canary was added.
\item The first deployment used the portal's \path{project-kit}; subsequent releases use \path{deploy.yml}. Both keep min instances 0 and max 1 to respect shared credits.
\item The course starter-kit zip was reviewed but deliberately \textbf{not} copied over: its \path{deploy.sh} still hard-codes a production JWT secret and prints a non-existent \code{/api/ready}. The hardened versions already on \texttt{main} were kept (R-02, R-12).
\item No real payment, e-mail, SMS or bank integration; all accounts are synthetic. The service is public, so no personal data is exposed without login.
\item AI agents were used for planning, drafting the runbook and evidence, and for script review as supervised by both members. Every gcloud/console change to billing, IAM or databases was executed by the human member. No secret value was ever pasted into an agent chat.
\item Screenshots are used only where a link cannot show the fact; API transcripts are explicitly labelled as transcripts, not screenshots. The service remains running until the instructor announces the end of grading.
\end{itemize}
